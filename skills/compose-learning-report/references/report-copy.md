# 三份报告的措辞规矩

`compose.py` 产出的文字直接可交付。本文件说明它为什么这么写，以及需要人工润色时哪些能改、哪些不能碰。

**总原则：三份都是给人看的，不是给系统看的。** 结构化数据在报告 JSON 里，文案里一个技术词都不该有。

## 通用红线

**一、层级不出口。** `A`/`B`/`C` 与层级名（拓展挑战 / 巩固提升 / 稳固基础）都不进 `student.txt` 与 `parent.txt`。层级是给系统排课的，不是孩子的身份。家长拿到会转述给孩子，效果和当面说一样。要表达怎么练就直接说题量与配比：「明天六道，两道基础四道阅读」。

**二、不跨会话。** 链路没有存历史。「本周第一次提升」「连续三天下滑」「最近状态不错」全部不能说——没有数据支撑。**唯一允许的对比是「本次 vs 摸底」**，因为 `mastery_delta` 的 `before` 来自画像，有据可查。

> `student-ability-tiering/references/report-format.md` 的家长同步示范文本里有一句「是本周第一次提升」，那是它自己也禁止的写法。**不要照抄那句。**

**三、对人说话用五档，不用百分比。** `已掌握 / 基本掌握 / 薄弱 / 严重薄弱 / 未接触`。一次会话通常 6–8 个计分点，摊到四个维度上常常每个只有 1–2 个点；「汉英转换 100%」是一道题算出来的。百分比会给出它撑不起的精度感，家长还会拿去跟别人家孩子比。计分点少于 3 的维度**直接不下判断**。

**四、不编出处。** `bank_available` 为 `false` 或 `locator` 为 `null` 时只说考点，不提课时题号。孩子翻开教辅发现对不上，比不给出处严重得多。

**五、纯文本。** 微信通道里 markdown 不渲染。不用 `#` 标题、不用 `|` 表格、不用 `**`。

**六、三份都不许漏技术语言。** 这条对教师版同样成立——教师版可以有教学术语（正确率、掌握度、错误类型），但**不能出现字段名、模块名、代码符号**。下面这些一个都不许进任何一份文案：

| 不能写 | 写成 |
| --- | --- |
| `seq2`、`qid`、`locator` | 第一轮第 2 题、教辅出处 |
| `build-learner-profile evaluate` | 摸底环节 |
| `profile_patch`、画像补丁 | 需写回学生档案的内容 |
| 置信度 medium | 本次数据中等 |
| `['词形变化', '语法辨析']` | 词形变化、语法辨析 |
| `None`、`null` | 未记录 |
| 层级 C、本层配比 | 学习路线：稳固基础、当前路线配比 |
| 计分点 / 得分点 | 小题 |
| 独立正确率 | 没用提示自己做对的比例 |
| 降级模式 | 本次全部为生成题 |
| 会话 JSON、字段、调用方 | 不出现，换成业务说法 |

`compose.py` 已经做了替换与过滤，**人工润色时不要把这些词加回去**。

## student.txt — 给孩子

四段式，对应方案场景四：**做了多少 → 哪个点拿下了 → 哪个点还欠着 → 明天先干什么**。

正确率对孩子报 `accuracy_with_hints`（含提示那个），不必强调「提示不算」——那是给系统用的口径，对孩子说会显得在扣分。`accuracy_independent` 只出现在 `teacher.txt`。

按层的风格差异（方案 3.3）：

| 层 | 风格 | 讲错题的方式 |
| --- | --- | --- |
| A | 启发式 | **不给答案**，把错题变成问题抛回去：「你回去把它重新想一遍，想出来告诉我你卡在哪一步」 |
| B | 引导式 | **给思路不给答案**：「明天我先给你个思路，你再自己试一遍」 |
| C | 陪伴式 | 慢节奏、多鼓励、全拆解，**先稳住信心**：「别急，这就是一条规则，规则扎住了这道题立刻就对」 |

**要像人说话，不要像播报。** 这是最容易做砸的地方：

| 别写 | 写成 |
| --- | --- |
| 今天一共做了 6 道题。8 个得分点里对了 6 个（75.0%）。 | 小宇，今天六道题，有两道没拿下。 |
| 先说今天最好的一件事。最要紧的是 X：…… | 最想跟你说的是 X。开头那两道你都栽在这儿…… |
| 这说明不是你学不会，是那条规则原来没扎住 | 所以不是你学不会，是这条以前没记牢 |
| 我们明天一起读一篇，我陪你一句一句找 | 明天我陪你读一篇，一句一句找 |
| 明天先过这一条：任务型阅读。过完我们再往下走。 | 明天就先弄这个，弄完咱们再往下走。 |

具体几条：

- **数字按「题」说，不按「得分点」说。** 孩子不知道一篇阅读算三个得分点。说「六道题，有两道没拿下」，不说「8 个得分点里对了 6 个（75.0%）」。
- **小数字用中文**，「六道题」比「6 道题」口语。量词前的 2 说「两」不说「二」。
- **结尾别重复上一段已经说过的考点名。** 「明天就先弄这个」就够了。

几条具体的：

- **叫名字。** 「小宇，今天做了 4 道题」比「同学，本次练习完成 4 道」亲近得多。`--name` 缺省时用中性称呼，**不编名字**。
- **同一考点重复错要说破**：「同一条今天栽了 2 次」。这比「你有两道错了」有用得多，因为它指向一条具体规则。
- **让孩子在书上做标记**：「书上 Unit 1 第 3 课时 II 第 6 题那道，标一下」。报告要能翻回教辅，这是「主角是教辅」的落点。
- **结尾不加范围免责声明。** 不说「只测了 Unit 1–2」「不代表整个英语水平」「不是给你贴标签」。要表达会变化就说积极的一句：「过完我们再往下走。」
- **粗心型不要降难度**，要点出「不是不会，是没看仔细」。降了更无聊、更粗心。
- 表情 🎉👍 一次一两个够了，别堆。

## parent.txt — 给家长

**只讲事实与下一步，不评价孩子。** 不写「他今天状态不佳」「注意力不集中」——链路没有测这些，写了就是编。

详略按层递增（方案 3.3）：A 层一句话带过，B 层加一句明天补什么，C 层再加一条家长能做的具体事。

C 层那条建议要**具体到可执行**，而且是「怎么帮上忙」不是「怎么盯着」：

> 可以做的一件事：让他把「by + 动名词」这条规则讲给你听一遍，讲得出来就是真会了。

方案场景四的原文结尾是「已同步到家长工作台，快去告诉妈妈你今天的进步吧」。本链路没有家长工作台，所以 `student.txt` 里不写这句；家长同步是否真的发出去，由通道决定。

## teacher.txt — 给老师和产品

唯一可以出现层级、置信度、样本量、画像补丁的地方。

必须保留的四项：

1. **每个维度的 `n`**，以及 `n<3` 时的「样本不足，不进升降层证据」标记
2. **分轮明细**——两轮不揉成一个数，第 1 轮错、第 2 轮同考点对，才看得出「是讲完才会的」
3. **`tier_recommendation` 连同它的置信度**，并注明判定权归 `build-learner-profile evaluate`，本环节只建议
4. **画像补丁摘要**，并注明需调用方合并、本环节不写画像

`data_gaps` 有内容就必须列出来。报告可以有缺口，但缺口不能是隐形的。

## 润色的边界

**能改**：措辞、语气、句子长短、把术语换成人话。

**不能改**：任何数字、任何脚本没给出的结论、出处。

具体说，这些都不能加——
- 脚本没算的对比（「比昨天好」）
- 脚本没标的判断（`n=1` 的维度说成「已经掌握了」）
- 报告里没有的出处（`locator` 是 `null` 却写出课时题号）
- 对孩子状态的评价（「今天很专心」）

一句话：**文字可以重写，事实必须原样。**
