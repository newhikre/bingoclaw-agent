# 学生能力分层与任务生成

## 本技能在链路中的位置

统一链路分四段：教辅数据录入 → **建立学生画像** → **按画像生成任务** → **学习报告与画像回写**，都由当前 Skill 的状态机编排。

前置条件是统一状态已通过 `profile_engine evaluate` 产出学习者画像。本阶段承担两件事，中间隔着一段真实的授课：

1. **出任务**——把画像翻译成一份可执行的学习任务：按已定层级选题，需要时生成变式题，交付任务包和话术。
2. **收作业**——孩子做完之后，用本次作答产出学习报告、家长同步与画像回写补丁。

两件事共用同一份任务包，所以放在一个技能里：报告的每一行数字都要对得上当初为什么选这道题。**只被要求出任务时就停在第四步**，不要自己编一份作答记录往下走。

练习报告不自动升降层；需要改变策略时，另建重测状态并重新运行 `profile_engine evaluate`。

难度只有两档，取教辅编者标注的 `part`：`基础夯实` / `能力提升`。不另建难度模型，不存在"压轴"这一档。能力维度只有四类：`词形变化` / `汉英转换` / `语法辨析` / `篇章理解`，映射规则见 `bank-contract.md`。

## 第一步，读画像，不重判层级

### 输入

输入是同一状态中 `evaluate` 的输出。**逐字段定义、取值枚举、11 条边界情况与 8 条入口校验清单全在 `profile-contract.md`，动手前先过一遍。** 这里只列本技能消费哪些字段：

| 画像字段                         | 用途                                               |
| -------------------------------- | -------------------------------------------------- |
| `strategy.code`                  | **直接作为层级**，A / B / C                        |
| `strategy.name` / `reason`       | 对孩子的说法、任务包的 `tier.rationale`            |
| `strategy.confidence`            | 证据强度，决定是否降档取题                         |
| `next_session.item_count`        | 本次题位数                                         |
| `next_session.difficulty_mix`    | 两档配比                                           |
| `next_session.feedback_style`    | 讲解风格，**取值有两套空间**，判定方式见契约第六节 |
| `next_session.focus_abilities`   | 选题锚点                                           |
| `next_session.focus_units`       | 候选池优先范围                                     |
| `next_session.exclude_qids`      | 去重                                               |
| `characteristics.error_pattern`  | 选题侧重与话术                                     |
| `characteristics.misconceptions` | 锚点细化，**常为空数组，空是常态**                 |
| `mastery.by_ability`             | 候选池优先级、首题挑选                             |
| `scope.units`                    | 出题范围的外边界，任何情况下不得越出               |

画像残缺不构成拒绝服务的理由，降级过程如实记进 `data_gaps`。

缺 `strategy.code`、画像范围或有效诊断证据时都不能生成任务；回到统一状态的诊断阶段补齐，不自行拍层级。

### 唯一的护栏：证据薄时降档取题

上游已经落实了判层的护栏（正确率、难度层覆盖、锚题占比），本技能不重复。本技能只处理一件上游没法处理的事——**证据强度对选题的影响**。

`strategy.confidence` 为 `low` 时，**难度配比按低一档执行，讲解风格仍用本层**。具体为 A 层用 B 层配比，B 层用 C 层配比，C 层不再降。

`medium` 不降档——上游给 `medium` 的常见原因是整套没用锚题或题量在 4 至 7 之间，证据偏薄但方向可信，直接降档会让大多数会话都被压到最低难度。`medium` 时改为把「能力提升」那一篇的定位调成拉伸：做不出来不计为失败，转提示阶梯。

依据是代价不对称：题目偏难会打击信心、浪费整节课时间，偏易只是效率损失一点，学生还能获得正反馈。风格不降的原因是风格错配比难度错配更容易被学生察觉，措辞与自身水平不符会被理解为不被认真对待。

降档时在任务包 `tier.downgraded_mix` 里写明，并在最后的判定说明里讲出来，不藏在 JSON 里等别人自己发现。

### 配比换算

`difficulty_mix` 是百分比（上游默认值为 A `30/70`、B `60/40`、C `85/15`，以画像里的实际值为准），`item_count` 是题位数，换算规则如下。**一篇「能力提升」材料按 2 个题位计**——它通常包含 3 个以上计分点，需要 5–8 分钟，不能与基础夯实单题等价。

| `mix.能力提升` | 能力提升篇数 |
| -------------- | ------------ |
| ≥ 60%          | 2            |
| 25% – 59%      | 1            |
| < 25%          | 0            |

```
基础夯实题数 = item_count − 2 × 能力提升篇数，最少 2
```

上游默认配比配 `item_count = 6` 时的结果：A 层 2 篇 + 2 道单题，B 层 1 篇 + 4 道单题，C 层 0 篇 + 6 道单题。

估算时长：`基础夯实题数 × 1.5 + 能力提升篇数 × 7` 分钟（基础夯实单题约 30 秒作答、1 分钟讲解），写入 `session.estimated_minutes`。C 层另加概念铺垫与示范题的时间，见该层手册。

**估时超过 `profile.available_minutes` 时砍一篇。** 篇数减 1、基础题数按公式重算，重算后仍超时就再砍基础题，砍到下限 2 道为止。这一条只在 A 层遇到短时段时触发（可用 15 分钟时默认配置估 17 分钟），砍完落到 1 篇 + 3 道单题、约 11.5 分钟。宁可少做也不要拖堂——摸底之后的第一次练习超时，学生对整套流程的预期就坏了。砍了要在 `data_gaps` 记一条。

## 第二步，按层级执行

层级确定后只读对应的那一份手册，三份全读会引入不相关的策略。

- A 层 · 拓展挑战 → `tier-a.md`
- B 层 · 巩固提升 → `tier-b.md`
- C 层 · 稳固基础 → `tier-c.md`

每份手册包含该层的学生特征、单次任务结构、选题规则、变式使用时机、讲解风格与话术模板、降级模式下的处置，以及该层最容易出现的失误。**题量与配比一律以画像字段为准，手册里的数字仅在字段缺失时兜底。**

三层共享的选题主干流程如下，各层的差异写在各自手册里。

### 选题主干流程

**第一步定锚点。** 取 `focus_abilities` 的第一项作为本次主锚点。`misconceptions` 非空时，锚点细化到具体那一条（例如「by 后的动名词误作不定式」比「语法辨析」可执行得多）；**为空是常态，此时锚点就停在能力维度层面**，不要为了细化去编一条误解。一次任务只攻一个主锚点，同时铺开三个维度会导致哪个都留不下印象。

锚点是「篇章理解」时有一条固定处置：**「基础夯实」层没有篇章类题目**，此时基础题改取与该篇考点相关的语法辨析或词形变化题——篇章题错在哪个语法点上，就用哪个语法点的单题打底。这是设计如此，不按候选不足处理。

**第二步限定范围。** 候选池优先取 `focus_units` 指定的单元。**`focus_units` 为空数组时回退到 `scope.units` 全部**——空数组表示学生没有做错的单元，不是"没有可出题的单元"，直接拿它筛会筛出零候选。无论如何不得越出 `scope.units`。

教材知识图谱与跨单元语法回溯在 Unit 1–2 范围内无用武之地，**不做前置依赖检查**；本教辅的语法要点是并列的，前置关系体现在同一考点内部的难度梯度上（见 `assets/scope-digest.md`）。

**第三步建候选池。** 按 `bank-contract.md` 第二节的规则遍历题库并过滤：`part` 不是两个难度层的跳过，`type` 不在能力映射内的跳过，`questions` 为空数组的跳过。过滤规则不在这里重复，以契约为准。

**第四步去重。** 排除 `exclude_qids` 里的题，匹配方式见 `bank-contract.md` 第四节——锚题按 `qid` 查定位表换算，生成题 id 忽略，四元组直接比。做错过的题不排除，订正本身具有价值。

**同一锚点连着几轮出现是常态**，`focus_abilities` 短期内不会变。此时锚点不动、换题型外壳（括号填空 → 中译英 → 单项选择），保证学生每轮拿到的是不同的题面而非同一道题。写回与轮换的完整规则见 `output-format.md` 的 `next_session` 一节。

**第五步按配比取题。** 首题选学生大概率做得对的那一道——取锚点维度里 `mastery.by_ability` 相对高的那一维、或同考点最简单的一道，开场受阻会影响整节课的状态。

**第六步处理候选不足。** 先放宽到同单元同考点的其他课时，再放宽到相邻能力维度，最后才触发变式生成补足。优先用原题的原因是原题的答案经过教辅人工质检，生成题不具备这层保障。

**第七步排序。** 整体由易到难，但不严格单调，在最难的一道之后插一道基础夯实题收尾，让学生带着完成感结束。「能力提升」篇章放在中后段，不放开头。

## 第三步，产出变式题

变式题的完整约束与自检流程见 `variant-generation.md`。要点是：

- **考点与词汇不得越出** `assets/scope-digest.md`。这一条与上游生成诊断题的约束相同，是硬边界，降级模式下同样不放松。
- 变式题必须自带 `acceptable_answers` 数组。英语填空常有多解（`loud` / `loudly`、`if` / `whether`），单一答案会把对的判成错的。
- 任何变式题在进入任务包之前都需要自己完整解一遍，并核对是否在考点范围内。

各层的变式使用时机不同，见各自手册。

## 第四步，交付

产出物有两样，缺一不可。

一是结构化任务包（JSON），供智能体调用，含层级来源、题目清单、答案、提示阶梯、异常分支。

二是引导话术，面向学生，按本层的讲解风格撰写。孩子的姓名与性格偏好从统一状态的 `learner` 读取；没有就用中性称呼，不编造。

**学生可见出处只说到单元**——原题和变式报所属单元，生成题只报考点。课时与题号保留在结构化任务包和教师明细中，不对学生或家长展示。统一规则见 `copy-policy.md`。

完整字段定义、必填项和一份填好的样例见 `output-format.md`。

交付顺序是先任务包，再话术，最后用两三句说明为什么选这些题、层级来自画像的哪一条判定。这段说明面向产品和老师，需要经得起追问。某道题的存在理由说不清楚时，这道题就不应该在任务包里。

**任务包发出去的同时，把这一轮追加进统一状态**：

```bash
python scripts/cycle_engine.py append-pack --state state.json --pack task_pack.json
```

这一轮做完再通过 `append-log` 回填作答。状态机自己配对任务与日志，调用方不用攒散文件；不要手工重写 `state.json`。

**到这里是一次交付的终点。** 孩子还没做题，没有作答记录就没有报告，不要接着往下编。

## 第五步，讲完之后出报告

孩子做完了、或者用户说「今天学完了」时才走这一步。完整字段定义、判分口径与话术要求见 `report-format.md`，动手前读它。

### 输入是任务包 + 授课记录，一次推题一对

任务包只有题和标准答案，**孩子答了什么要靠讲题时边讲边记**——每道题记会话内唯一 `item_id`、展示用 `seq`、原样 `response`、用掉几级提示，可选记秒数。记录的字段表在 `report-format.md` 第一节。

**一次推题是 n 道题，推了几次就有几对任务包与记录**，都在会话文件里按轮次排好（第四步已经追加过任务包，这里回填记录）：

```bash
python scripts/cycle_engine.py append-log --state state.json --log round1_log.json
```

做完一批还有时间、或者错得多要补一批，可显式运行 `append-pack ... --continue-before-report` 产生第二轮。报告保留逐轮记录，再给跨轮汇总——第 1 轮做错、第 2 轮同考点做对，两条都留着才看得出「是讲完才会的」。

**没有作答记录就停下来索要，不要用「大概做对了四道」这类转述凑一份。** 报告的全部价值在于它对得上每一道题；转述出来的报告翻不回书上那道题，也没法回写画像。

### 数字由脚本算

```bash
python scripts/cycle_engine.py report --state state.json --out-dir report-out
```

统一入口固定读取状态中的所有未报告完整轮次。汇总正确率是这些轮次的计分点合起来算，不是各轮正确率取平均。**以脚本结果为准，不手算正确率、不为了让报告好看凑数**。答案归一化与 `profile_engine` 同口径，孩子多写个句号、大小写不一致都不判错。

判分只有一条需要在这里强调：**用了提示才做对的题不计入独立掌握**。会做和被扶着做不是一回事，这条放松了掌握度就会一路虚高，下一轮直接给孩子推超纲的题。报告同时给 `accuracy_independent`（回写画像用）与 `accuracy_with_hints`（对孩子说的那个）。

### 交付三样

一是**报告 JSON**，含 `rounds[]`（推了几次就有几条）、跨轮汇总、错题清单（每条带轮次与出处）、掌握度变化、`tier_recommendation` 与 `profile_patch`。

二是**收尾话术**，面向孩子，按本层讲解风格写：今天做了多少 → 哪个点拿下了 → 哪个点还欠着（带出处让他在书上圈） → 明天先干什么。

三是**家长同步**，详略按层递增（A 一句话结果，B 加明天练什么，C 再加一条具体的陪伴动作），只讲事实与下一步。**不评价孩子**——「今天不太专心」这类主观印象没有任何字段支撑，家长转述给孩子就成了一顶帽子；用时超了就说用时超了，做到第几道就说第几道。

**说给人听的两样里都不出现层级**——代号 `A`/`B`/`C` 与层级名都不说，`tier_recommendation` 更不能说成「你要升层了」。层级是给系统排课的，不是孩子的身份，家长转述一句同样等于说给孩子听。要交代怎么练就直接说配比与题量，见 `output-format.md` 话术一节。

`profile_patch` 汇总本次用题、实测掌握度和错误模式，由 `cycle_engine.py report` 自动合并回统一状态。`tier_recommendation` 只是下轮重测建议，单次练习不会改变策略。

## 降级模式

题库读不到时**照常产出完整任务包**，但全部题目改为生成题。完整的行为契约见 `bank-contract.md` 第五节，三条最关键的：

1. **考点边界不放松。** `assets/scope-digest.md` 是内置的，任何环境下都可用，没有理由越界。
2. **不写 `locator`，话术不提课时与题号。** 编造精确出处比不给出处严重；各层话术都按 `copy-policy.md` 只说 Unit 或考点。
3. **每道题都要过一遍变式题的自检**，不只是变式题——降级模式下所有题都没有人工质检背书。

任务包写 `bank_available: false`，`data_gaps` 记明原因。层级判定、配比换算、话术风格全部照常，这些只依赖画像，与题库无关。

**报告环节同样受影响**：`follow_up` 里的 `locator` 一律为 `null`，收尾话术与家长同步都不提课时与题号，只说考点。判分、统计、`profile_patch` 不受影响，生成题的 `acceptable_answers` 一样能判。

## 几条不做的事

- **不重新判层。** 层级、置信度、强弱项、错误模式全部来自上游画像，本技能只消费；报告里的 `tier_recommendation` 是建议，不是判定。
- **不编作答记录。** 没有授课记录就不出报告，转述凑出来的报告回不到具体那道题。
- **不合并轮次。** 推了几次就有几条 `rounds` 记录，两轮的表现不揉成一个数。
- **不把层级说给孩子或家长。** 代号与层级名都不出口，只说今天练什么、怎么练。
- **不评价孩子。** 家长同步只写作答事实与下一步，主观印象不写。
- **不擅自做跨会话趋势。** 状态虽保留观测历史，但本版没有周趋势算法，不能说「连续三天下滑」。
- **不引入第三档难度。** 教辅只标了两档，"压轴"是没有数据支撑的臆造分层。
- **不引用不存在的资料。** 题库里没有页码字段，就不写页码；学生和家长只标注单元。精确课时仅供内部回源与教师明细。
- **不改题库资产。** 本 Skill 内置的题库只读；运行态状态、日志和报告写到调用方指定目录。
- **不整份重写状态。** 一律用 `cycle_engine.py`，旧轮次不能被覆盖。
- **不重复消耗教辅题。** 本次用题由报告自动并入画像排除项；普通任务命中历史原题会被门禁拒绝，只有显式订正复练可放行。

## 已知缺口

- 教辅题库中「听力」需要音频、「写作」与「自主检测」无法自动判分，三者都不进任务包。
- 非锚题在题库里没有稳定 `qid`，跨会话去重依赖四元组定位，题库重新抽取后定位会失效。
- `anchor_bank.json` 读不到时，那 12 道锚题可能被重复推送，这是可接受的降级。
- 统一状态的 `learner` 携带已采集的姓名与性格偏好；没有采集到的字段仍保持缺省。
- 授课记录靠讲题时自觉记，**漏记 `hints_used` 会让掌握度虚高**，脚本无从校验。
- 报告只覆盖当前未报告轮次，掌握度变化量是「本次 vs 画像中的前次记录」，不是周趋势；`cycle_engine.py` 会自动合并补丁供下一轮选题。
